# RB-002 — Missing Environment Variables

- **Runbook ID:** RB-002
- **Title:** Missing Environment Variables
- **Affected technology:** Docker Compose (`environment`, `env_file`)
- **Risk level:** Low (configuration fix; no data risk)

## Symptoms

- Container starts then exits, or the app serves 500s on every request.
- Logs show `KeyError: '<VAR>'`, `os.environ[...]` failures, `undefined variable`, or database client errors citing empty host/user/password.
- DeployIQ evidence: `exception` category with `KeyError`/`environ`, or repeated HTTP 500s (see RB-007).

## Possible causes

1. Variable declared in `environment:` but missing from the shell/`.env` file Compose interpolates.
2. `env_file` path wrong or file not mounted into the container context Compose reads.
3. Typo in variable name (`POSTGRES_DB` vs `POSTGRES_DATABASE`).
4. Variable set on the wrong service (e.g. set on `web` but needed by `db` migration container).

## Diagnostic steps

1. `docker compose config` — render the interpolated Compose file and check the service's `environment:` block resolves to real values (empty values show the bug immediately).
2. `docker compose exec <service> env | sort` — list what the running container actually received.
3. Compare against the application's required variables (settings module / README).
4. `docker logs <container> --tail 50` — match the missing name in the traceback to the env list.

## Verified remediation

- Add the missing variable to the service's `environment:` map or the referenced `env_file`, then `docker compose up -d --force-recreate <service>`.
- For secrets, prefer Docker secrets or an env file excluded from version control over inline `environment:` values.

## Verification steps

- `docker compose exec <service> env | grep <VAR>` shows the expected value.
- Application boots without `KeyError`; DeployIQ stops updating the incident (no new matching lines).

## DeployIQ notes (our recommendation, not vendor documentation)

- Secret-like values (`api_key`, `token`, `password`) found in logs are redacted before storage and are never sent to the AI backend.
